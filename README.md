# CintyezOS

> 现在的 AI 手机，是在手机上装了一个 AI。
> 我们想做的是，让手机本身成为 AI。

CintyezOS 是一台手机操作系统的设计稿，也是一份路线图：把 AI 从“一个需要主动打开的 App”，变成住在系统里的主体。它读你的通知、认识你的应用、替你操作，并在你使用手机的过程中学会新能力。

仓库现在主要还是一份可交互的 HTML 设计稿，外加一个能安装的 Android 外壳。它不是操作系统，但它把操作系统应该长什么样、怎么动、先验证什么，完整地演了一遍。

## 在 Android 上试

[下载最新 APK](https://github.com/Tsimin-ORGANIC/CintyezOS/releases/latest)（`CintyezOS.apk`，Android 8.0+，调试签名，安装时需要允许安装未知来源应用）。

APK 不是另写的一套前端：GitHub Actions 每次把同一份 [`kemon-os-v2.html`](kemon-os-v2.html) 同步进一个全屏 WebView 外壳再打包。推送到 `main` 会自动构建，并更新上面这个下载。想在浏览器里看设计稿，直接打开 HTML 即可。

> 0.1.5 起修复了启动闪退（Android 11+ 都会触发），已在 Android 13 / 15 模拟器上验证可以正常启动。

## 名字

**Cintyez** 来自俄语 Синтез——合成。

不是“把 AI 装进手机”的合成，而是几件本来分开的东西开始长在一起：应用的能力、重复的操作、散落的信息，以及一个有人格的智能体。系统的名字就是这个动作。

**Kemon** 是住在系统里的那个 AI，全名 Kemon Cintyez。这个名字来自一个搁置的项目——ORGANIC。在那份设定里，Kemon 取 “Chemy-on” 的谐音，指向元素的变化与焰色反应；Cintyez 是姓。她白发，发梢会按交互状态变成不同金属的焰色——这套视觉锚点还没有进 UI，但迟早会回来。

那个项目没有做完。她留了下来。

现在 CintyezOS 是她的身体。名字、人格和“本地优先”的脾气带过来了；ORGANIC 那套桌面与全屋架构没有搬——这里要长的是另一副身体。

## 一、为什么现在的手机做不到

今天的“AI 手机”，本质还是“在手机上装了一个更聪明的 App”：

- 你要先打开它，它才知道你想干什么；
- 它看不见你的通知、你的应用、你刚才在做什么；
- 你的信息被切成几十份，散在微信、邮件、日历、待办、资讯里，最后还是要你一个个点开；
- 桌面还是十几年前的图标网格：找到图标，打开，用完，退出。

模型已经会调用工具了，手机却还没有把“工具”交给它。

CintyezOS 要补的就是这一层。

## 二、四个支柱

四个支柱不是四个功能，而是四次合成：把应用的能力合成为工具，把重复的操作合成为经验，把分散的信息合成为判断，把散落的图标合成为注意力。

### 1. 工具箱

手机上的每一个能力，都应该能被注册成工具：发消息、查日程、改地址、提交审批、叫车、记账。

Kemon 不模拟手指去点按钮，它直接调用能力。工具是系统的公共接口，应用只是工具的一个来源。

### 2. 观察学习与“万能胶水”

Kemon 记录两股流：**你怎么操作手机**，以及**模型怎么调用工具**。

重复出现的动作会被抽成一个新工具。比如你每周五都要“把评审改到下午、订会议室、在群里说一声”，这三步会被粘成一个叫“改评审”的工具。下次你只说一句，它就知道要动哪几个函数。

这是整个项目里最激进、也最没有先例的部分。我们不打算靠训练模型解决，而是靠函数调用轨迹的积累——胶水层在系统里，不在模型里。

工具一多，上下文就会爆炸。所以还需要一层按情境挑选工具的路由（类似 MoE）：此刻是在聊天、在导航、还是在处理工作，只把相关的十几个工具交给模型。

### 3. 信息主权层

信息不该由应用决定你什么时候看、看多少。

Kemon 维护一份白名单信息源，替你读完，再按**紧急、人际、事务、资讯**重新组织。锁屏就是收件箱：你不需要打开十个 App 确认今天有没有事，扫一眼就知道。

信息的入口在你这儿，不在 App 的角标上。

### 4. 新桌面

桌面不是图标仓库，是注意力的地图。

应用按重要度分布在一个可以被拖动、被放大、被聚焦的空间里；中心是一块固定的凸透镜，越靠近越清晰。你先聚焦，再打开——把“找”和“进”拆成两个动作。

长按一个应用，可以把它加为 **Agent 对象**：从这一刻起，这个应用里的操作可以交给 Kemon。

## 三、一次开机

这是设计稿里已经能完整走一遍的流程：

1. **锁屏**。通知已经被 AI 分好组：三条紧急、三条人际、三条事务、三条资讯。底部左滑，列表收拢成四组；再点一组，展开细节；继续左滑，进入单条通知。
2. **上滑解锁**。指纹之后不是直接进桌面，而是一道重力波从屏幕底部扩散、碰撞、坍缩，最后收成一个点——奇点。
3. **主屏**。奇点展开成一句话，逐字流出来：**“我们要构建什么？”** 下面是输入框和语音球。
4. **三指收拢**，进入应用矩阵。三十个节点按重要度分四环排布，拖动环视，单击聚焦，再点打开，长按加入 Agent 框。

整段流程不出现一次“桌面图标网格”。

## 四、现在到哪一步

当前设计稿：[kemon-os-v2.html](kemon-os-v2.html)。单文件、零依赖，浏览器直接打开，手机体验最佳。它继续作为可交互展示，也是信息层先落地的地方；新功能先加在这里，真撑不住再拆。

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 锁屏四种状态（平铺 / 分组 / 展开 / 详情） | 可交互 | 数据为 12 条假通知 |
| 锁屏手势与滚动 | 可交互 | 触屏 + 鼠标双通道，滚动与滑动做了方向仲裁 |
| 上滑解锁 + 重力波动效 | 可交互 | 2D 波方程高度场，约 1.3 秒 |
| 主屏提示流、输入框、语音球 | 视觉完成 | 输入不接模型，提交后直接进矩阵 |
| 应用矩阵（30 节点 / 四环 / 透镜 / 聚焦） | 可交互 | 拖拽、惯性、视点滑行、点选 |
| 长按菜单 / Agent 框 | 视觉完成 | 加入后只生成 chip，不参与任何对话 |
| 打开应用 | 占位 | 一个 1.25 秒的假启动页 |
| Android 壳 / APK | 可安装 · 已验证 | 全屏 WebView；Android 13 / 15 模拟器启动验证通过 |
| 模型接缝 | 已完成 | `window.kemon.chat()` 已留，未发真实请求 |
| 轻量工程化 | 未开始 | 先定三层与 hooks，不引入构建 |
| 真实通知、真实应用、事件流、模型调用 | 未开始 | 无后端、无持久化、无权限 |

一句话：**“它可以长这样”已经证明了；“AI 真的在里面干活是什么感觉”还没有。**

## 五、路线图

先定一条总原则：**前端只有一份，就是 `kemon-os-v2.html`。** 浏览器和 Android WebView 共用它；不引入框架、构建步骤和数据库。工程优化只做“把数据、钩子和界面分开”，不做“换一套技术栈”。

只有一种情况才升级：HTML 真的撑不住——单文件太大、改一处要动三处，或者目标机器上的 WebView 跑不动。到那时再拆，不提前。

### 分层规则（先定这个，再写功能）

只分三层，同类东西只放一层：

1. **前端（HTML）**：界面、手势、动效、纯格式化函数。简单、无副作用的函数直接内嵌，不再拆文件。
2. **数据层（HTML 里的 `Info` 模块）**：拉取、归一化、缓存。所有来源都输出同一种 `DigestItem`，界面只认这个形状，不关心数据从哪来。
3. **能力层（单独的 Android 模块/服务）**：需要系统权限、应用数据、后台运行、跨应用操作的部分——通知、使用记录、自动化工具。它通过 `window.kemon.hooks` 把结果交给前端，不把权限逻辑写进 HTML。

一条判断规则：**碰系统权限/跨应用/后台的，放能力层；只是拉网页数据、做缓存和排版的，放数据层；只跟界面有关的，内嵌。** 不要出现“这个 fetch 写在点击事件里、那个 fetch 写在数据层”的情况。

分层是逻辑边界，不是目录数量；不需要为了看起来工程化，把每个函数都拆成文件。

```text
HTML（前端 + 数据层）
  界面 / 手势 / 纯函数
  Info：source → normalize → digest
        ↕  window.kemon.hooks（版本化 JSON）
Android 能力模块（单独写，但先放在同一个 APK 里）
  system：通知 / 应用数据
  tools：AI 自动化动作
  native：返回键 / 主题 / 安全区
```

`info` 由 HTML 数据层实现；`system` / `tools` / `native` 由 Android 模块实现；`observe` 横跨两边，只写本地事件。新增信息源只实现 `source`，新增动作只实现 `tool`，前端不改。

### 现在：先确认 WebView 能不能跑（v0.1.x）

- 设计稿阶段已经完成：给任何人看三十秒，他能说出“这不是普通桌面”。
- Android 壳能构建、安装、全屏加载；启动闪退已修复（根因：`onCreate` 里过早取 `WindowInsetsController`），CI 冒烟任务会在 Android 13 / 15 模拟器上验证启动。
- 真机遇到问题时的时间盒：装 [platform-tools](https://developer.android.com/tools/releases/platform-tools)，开 USB 调试，用 `adb logcat -b crash` 抓 `FATAL EXCEPTION`；一次会话内能定位就修，定位不了就记录机型、复现步骤后挂起。
- 兼容目标只选一台两百元档实验机；老机器的 WebView 版本单独记录，不承诺全版本。

**决策点**：如果 WebView 在目标机器上能稳定跑 HTML，就继续用 HTML 做唯一前端；如果跑不动，再讨论换壳或用浏览器 / PWA，而不是先重写前端。

### 阶段 1：HTML 信息层（最轻的一版）

要回答：**AI 重排信息后，你会不会少打开 App？**

- 在现有 HTML 里加一个信息层视图，不重写锁屏、矩阵和开机动画。
- 数据层先写成几个普通函数/对象：`source`（拉取）→ `normalize`（统一）→ `group`（四组）→ `summarize`（模型）→ `render`（界面）。不建目录、不上构建。
- 先跑 `mock` 数据，把界面和分组逻辑调顺；再接第一个真实源（优先 RSS/Atom 或日历 ICS）。
- 缓存先用 `localStorage` / 内存；不上 SQLite，数据量真大了再说。
- 模型调用走现有的 `window.kemon.chat()`，在它里面补真实 `fetch`；如果接口被 CORS 挡住，再加一个**单文件 `proxy.js`**（无依赖，只转发），不建完整后端。
- 指标只记：看了多少条、点开几个 App、处理一轮多久。先自用 3 天，不做复杂埋点。

完成标志：信息层能显示真实或半真实数据，连续自用 3 天，主观上减少打开 App。若没减少，就停，不继续加功能。

### 阶段 2：钩子层（仍然在 HTML 里）

- 不引入 TypeScript、不建工具服务器；在 `window.kemon` 上加一个 `hooks` 对象，带 `version`。
- 先五个：
  - `info`：信息层对外的取摘要/刷新接口（HTML 数据层实现）；
  - `system`：通知、前台应用、使用记录（原生模块提供）；
  - `tools`：列能力、调能力（原生模块或公开 API）；
  - `native`：返回键、主题、安全区；
  - `observe`：记录用户操作和工具调用，只写本地。
- 用 JSDoc 写清参数和返回值；写操作先弹确认，读操作可静默。
- 完成标志：信息层只通过 `kemon.hooks` 拿数据；以后换数据源不改界面。

### 阶段 3：Android 系统入口（可选，不阻塞）

- 修完闪退后，先只做一个实验：通知监听。无障碍、桌面替换等真需要再上。
- 能力层先做成同一个 APK 里的独立模块/服务，不拆第二个 APK；权限和跨应用通信会因此复杂一截。
- 每个入口记录：能拿到什么、拿不到什么、耗电多少。
- 产出“Android 能力清单”，再决定钩子层补什么。

### 阶段 4：动作层（信息层跑通后）

- 先接 1–2 个有公开 API 的工具（建日程、草稿邮件）；没有 API 的不做。
- 工具放在能力层，不在 HTML 里直接调系统 API；前端只负责确认界面。
- 确认界面必须有：Kemon 先给方案，用户点头才执行。
- 记录工具调用轨迹，留给观察学习。

### 阶段 5：观察学习与 AOSP（以后）

- 观察学习：只有前几步积累到真实事件流才做；不训练模型，只做“轨迹 → 工具”。
- AOSP：只有通知监听、无障碍、桌面替换都证明“差一层系统权限”才做。
- 失败就承认它是“好看的 AI 桌面”，不硬撑成 AGI。

### 止损线

- 信息层跑不通：重排没有减少打开 App → 回到设计稿。
- WebView 跑不动：目标机器上不稳定 → 再考虑换壳，不重写前端。
- 观察学习跑不通：轨迹无法固化成工具 → 承认它是设计概念，不包装成 AGI。

**如果只记下一步：** 在 HTML 里跑通 mock 信息层 → 接第一个真实源。

## 六、硬件设想

目标是一台便宜、开放、能随便刷的 Android：

- 二手，两百元档；
- 尽量 8GB 内存；
- bootloader 可解，有 LineageOS 或接近 AOSP 的包；
- 电池健康比跑分重要。

考虑过小米 8、LG V40 这类老旗舰。日常主力机（Redmi K80）不刷，实验机单独一台。

硬件不是现在的瓶颈。真正的瓶颈是：系统级的 AI 到底该做什么、不该做什么。

## 七、设计原则

1. **先有判断，再要确认。** 系统先分组、先摘要、先排序，用户只负责点头或改。
2. **动效负责空间感，不负责热闹。** 每一次放大、位移、坍缩都在回答“我从哪来、到哪去”。
3. **一屏只做一件事。** 锁屏是读信息，主屏是提需求，矩阵是选对象。
4. **能用一根手指，就不用三根。** 三指进矩阵是例外，因为它是一次“换视角”，不是日常操作。
5. **假数据可以，假结论不行。** 原型允许 mock，但每个交互都要能回答一个真实问题。
6. **能力走钩子，不走模拟点击。** 系统把信息、工具、事件流包成带版本的钩子；Kemon 调能力，不点按钮。

## 八、先不做的事

- 不做通用聊天界面。Kemon 的对话发生在系统需要它的地方，而不是一个聊天列表里。
- 不做应用商店、不做账号体系、不做云同步。
- 不在设计稿里接真实账号；信息层只接只读、由你自己配置的信息源，写操作必须确认。
- 不为了工程化另起一套前端。HTML 能跑就一直用；真撑不住再拆。
- 不把权限/跨应用逻辑写进 HTML，也不把简单纯函数硬拆成模块。
- 不为所有 Android 版本做兼容。先认一台实验机，其他版本只记录、不承诺。
- 不追商业化。这是一个个人项目，先证明它值得存在。

长期方向是本地优先：信息尽量留在设备上，模型调用按需发生。设计稿不涉及真实隐私数据；信息层能只读就只读，能不离开设备就不离开设备。

## 九、仓库与运行

```text
kemon-os-v2.html      唯一前端（浏览器 / Android WebView 共用，单文件，无依赖）
kemon-os.html         v1 存档
.workbuddy/memory/    迭代笔记（手势、滚动、绘制层级等踩坑记录）
README.md
```

如果后面必须加代理，也只是一个单文件 `proxy.js`，不建 `server/` 目录。

直接用浏览器打开 `kemon-os-v2.html`。桌面端可用快捷键：

| 按键 | 作用 |
| --- | --- |
| `Space` | 锁屏解锁 / 进出矩阵 |
| `↑` | 锁屏上滑解锁 |
| `G` | 平铺 / 分组切换 |
| `1`–`4` | 展开对应通知组 |
| `Esc` | 返回上一级 |
| `T` | 切换明暗主题 |

手机端：上滑解锁、左滑分组、右滑返回、三指收拢进出矩阵。

## 十、术语

- **CintyezOS**：系统名。Cintyez 来自俄语 Синтез（合成）。
- **Kemon**：系统里的 AI 主体，全名 Kemon Cintyez。不是助手，是常住者；人格设定继承自 ORGANIC。
- **ORGANIC**：Kemon 人格与“本地优先”思路的来源，一个没有做完的项目。
- **Agent 对象**：被交给 Kemon 代操作的应用。
- **钩子**：系统交给 Kemon 的能力契约（`info` / `system` / `tools` / `native` / `observe`），带版本，替代模拟点击。
- **万能胶水**：把观察到的函数调用固化成新工具的机制。
- **信息主权层**：由用户定义信息源、由 AI 重排信息的中间层。
- **奇点**：开机动画里重力波坍缩成的那个点；也是主屏对话的起点。
- **透镜**：应用矩阵中心固定的放大区，用来表达“注意力的焦点”。

## 边界

这是一个人的项目，从一台两百块的二手手机开始。

它现在是一份设计稿，不是产品，更不是 AGI。README 里所有关于“学习”“代理”“主权”的描述，都是设计意图，不是已实现的功能。

如果你只记住一句话：

**手机不该是装 AI 的容器，它应该就是 AI 的身体。**
